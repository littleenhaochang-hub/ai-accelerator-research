Technical Report: End-to-End Extreme Quantization for LLM Inference

Date: April 2, 2026
Target Architecture: Qwen2.5-0.5B-Instruct
Focus: A4KV4 (Hadamard Attention) & W4A4 (Block 32 FFN)

1. Background

Modern Large Language Models (LLMs) and Test-Time Compute (TTC) reasoning engines are heavily constrained by the Memory Wall during autoregressive decoding. While computing power (ALU TFLOPS) scales quadratically, memory bandwidth (DRAM/HBM) scales linearly. To achieve high token generation rates, the industry relies on quantization. While Weight-Only 4-bit (W4A16) is mainstream, deploying true A4KV4 (4-bit Activations + 4-bit KV Cache) remains the holy grail for extreme edge deployment and high-batch-size cloud inference.

2. Problem Statement

Pushing KV cache and continuous activations to 4-bit suffers from Catastrophic Forgetting via the Outlier Wall. Neural network activations exhibit severe numerical outliers (often >100x the mean) driven by non-linearities like SiLU and Softmax peak concentration. Under standard 4-bit integer quantization, a single outlier expands the scaling factor for the entire vector, crushing 99% of normal features into zero (dead neurons), rendering the model's output as pure random noise.

3. Theoretical Foundation

To bypass the Outlier Wall, we evaluated two distinct mathematical approaches tailored to specific pipeline bottlenecks:

  • Attention Pipeline (A4KV4) - Hadamard Orthogonal Smearing: We apply a fixed 2D Hadamard Transform to the KV Cache before it hits memory. Because the Hadamard matrix is orthogonal ($H^T H = I$), it acts as a frequency mixer, "smearing" extreme token and feature outliers across all dimensions evenly. This smooths the distribution perfectly for 4-bit quantization. During the $Q \times K^T$ dot product, the transformation is mathematically reversed.
  • FFN Pipeline (W4A4) - Sub-vector Micro-Scaling (Block 32): Because FFN layers use SiLU (which destroys orthogonal rotation properties), Hadamard fails here. Instead, we adopt a hardware-centric micro-scaling approach similar to OCP MX4. By breaking vectors into chunks of 32 elements (Block 32) and assigning an independent FP16 scaling factor to each block, we physically isolate outliers. An outlier only degrades its local 32-element neighborhood, preserving the 4-bit fidelity of the remaining network.

5. Conclusion & Silicon Architecture Recommendations

  1. FFN ALUs must natively support Block 32 Micro-Scaling: The W4A4 FFN experiment definitively proved that pure 4-bit integer MACs fail. Next-gen AI Accelerators must adopt Block-32 (or Block-16) FP16 scale fetching tightly coupled with INT4 dot-product engines.
  2. Hadamard KV Cache Needs 1D Refinement: The 2D Hadamard transform failed on variable-length sequential decoding. The memory controller should be redesigned to apply 1D Hadamard smoothing exclusively on the Feature Dimension (which is fixed length), paired with SmoothQuant logic to handle sequence expansion.

By marrying 1D Hadamard KV4 Memory Controllers with Block 32 W4A4 ALUs, we can construct an AI Accelerator that completely shatters the Test-Time Compute memory wall without sacrificing cognitive reasoning.
