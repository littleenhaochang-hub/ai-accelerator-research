🚀 一、 Gemma-4 26B A4B 真實物理微觀拆解

要讓高達 25.2B 參數的巨獸在 8GB 手機上流暢執行，我們必須針對 Gemma-4 的官方架構進行最嚴酷的物理重構。

2. 模型分區與 LFU 記憶體策略

  • [必讀區] 核心共享權重 (1.2 GB): 包含超大詞表 (~0.7 GB) 與 1B 參數的共享專家 (Shared Expert, ~0.5 GB)。這 1.2 GB 必須無條件永久常駐 (Pinned) 在 DRAM 中。
  • [動態區] 獨立路由專家 (11.4 GB): 切分為 30 層 × 128 個專家 = 3840 個獨立神經網路。單一專家極度輕量化，僅 3.04 MB！每次生字喚醒 8 個專家 (24.3 MB)。
  • 🔗 實證程式碼：Flash 串流推論引擎原型 (驗證 221MB RAM 佔用極限)
  • 🔗 實證程式碼：動態專家非同步串流引擎 (驗證 I/O 負載狂砍 85%)

🧠 二、 實證剖析：千筆 Prompt 軌跡驅動命中率 (Trace-Driven Profiling)

既然 128 個專家無法全部放進 DRAM，我們必須依賴「齊夫定律 (Zipf's Law)」與真實語料軌跡來建構 逐層最少使用常駐 (Layer-wise LFU Pinning) 策略。

2. 實測結果分析

在模擬 8GB 手機 (AI 預算 5.0 GB，扣除 1.2GB 必讀區後剩餘 3.8 GB) 的情況下，我們可以在每一層鎖定 42 個熱門專家 (42/128，佔單層容量的 32.8%)。這 42 個被標記為 PINNED 的專家，在 1000 筆 Prompt 測試中成功攔截了 87.3% ~ 88.6% 的快取請求！

🛠️ 四、 軟硬體協同設計規格 (HW/SW Co-Design)

要實現上述物理極限，下一代 Edge NPU 必須包含以下矽晶層級 (Silicon-level) 與 OS 改動：

  1. OS 記憶體割讓 (Memory Carve-out): 鎖定 1.2GB 專門用於 Shared Weights (包含 256K 詞表與 1B 共享專家)。剩下空間切為 Layer-wise 專家常駐池。
  2. 離散收集引擎 (Scatter-Gather DMA): 針對 Top-8 路由特化： 硬體 DMA 必須原生支援深層 SG-List，一次性將 8 個散落於 Flash 的微型專家位址抓齊並在背景拼成連續矩陣。
  3. NPU-Direct UFS DMA & Ping-Pong SRAM: 繞過 CPU 中斷，直通 UFS 提取資料。雙埠 SRAM 在 Cycle 1 計算 Buffer A，Cycle 2 背景寫入 Buffer B，達成零等待管線 (Zero-wait Pipeline)。
  4. 專屬極早期路由 ALU (Early-Router ALU): 確保 Router 特徵一到，小型 ALU 即刻算出結果並觸發 DMA 預取，不與主 MAC 陣列搶佔佇列。
