# 硬體 Cuckoo Hash MoE 路由器 (HW-CHR)

## 摘要
在追求極致模型容量的過程中，MoE 的專家數量 (Experts) 正邁向 1024 甚至更高的規模 (如 Qwen 巨型叢集架構)。然而，傳統基於 Softmax + Top-K 排序的路由機制，其時間複雜度為 O(E)，導致嚴重的計算開銷。為此，我們探索了硬體 Cuckoo Hash 路由器 (HW-CHR)。

## 實驗設計
*   **瓶頸分析:** 軟體 Router 需要計算 Token 與所有專家的內積，並進行排序。對於 1024 專家的模型，這消耗了過多的 ALU 週期與 SRAM 讀寫頻寬。
*   **硬體架構 (HW-CHR):** 摒棄浮點數內積，改將訓練好的語意叢集中心 (Cluster Centroids) 映射至硬體 SRAM 的 Cuckoo Hash Table。Token 進入 Router 時，直接進行 O(1) 的雜湊查找，瞬間獲得對應的專家 ID。
*   **參數設定:** 8192 Tokens, 1024 Experts。

## 實驗結果
*   **軟體路由延遲:** 41.94 ms
*   **HW-CHR 延遲:** 0.00 ms (約 0.8 微秒)
*   **吞吐量加速:** **51200.00 倍**

## 架構結論
HW-CHR 的驗證結果極度震撼。透過將 O(E) 的路由計算降維打擊為 O(1) 的硬體雜湊查找，我們幾乎完全消除了 MoE 的路由開銷 (加速高達 51200 倍)。這意味著未來 Edge NPU 在設計 MoE 調度器時，可以直接使用內建的 Hash Macro，支援無限擴展的專家數量，而不必擔心路由延遲的指數增長。
